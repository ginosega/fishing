## Recommended topology

`GitHub Actions trusted runner` → **future Cloudflare Access service-token authenticated HTTPS ingress** → `fishing-p3-access-ingress-sandbox` (separate Worker, policy + signed JWT verified locally) → **Cloudflare Worker service binding** `P3_COMMAND_SERVICE` → `fishing-p3-command-bridge-sandbox` (existing no-public-URL Worker, currently static HTTP 503) → native isolated D1.

Cloudflare documents Worker-to-Worker service bindings without public URLs, with the caller declaring `{binding:"P3_COMMAND_SERVICE",service:"fishing-p3-command-bridge-sandbox"}` in its own configuration. <https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/>. GitHub Actions cannot invoke a Worker service binding directly.

Cloudflare Access recommends **service auth policy** with a restricted service token for headless clients; Actions sends `CF-Access-Client-Id` and `CF-Access-Client-Secret` to the policy-protected future ingress hostname. <https://developers.cloudflare.com/cloudflare-one/access-controls/authenticate-agents/>. Cloudflare provides an application JWT in `Cf-Access-Jwt-Assertion`; origins should verify its **signature, `iss`, app `aud`, `exp`**, and allowlist the signed service-token `common_name`, because a header alone is spoofable. <https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/>; <https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/application-token/>.

## Source modules

- `src/p3-access-jwt-verifier.mjs`: verifies Access JWT **RS256** via WebCrypto with an explicitly injected JWKS requester restricted to the configured `https://<team>.cloudflareaccess.com/cdn-cgi/access/certs` URL. Enforces immutable issuer, audience, exact service Client ID in `common_name`, service-only `sub=""`, app token `type`, timestamps, max token/JWKS sizes, key ID/algorithm consistency, fail-closed key rotation failure, redacted errors. No default JWKS network fetch.
- `src/p3-access-ingress.mjs`: source-only request/forwarding composition. Requires **separate ingress flag AND write flag AND trusted operator approval** before *any* request processing. Requires exact configured HTTPS origin and hardcoded `POST /p3/internal/accept`. Validates Access JWT using the injected verifier, then reads up to 8 KiB and sends ONLY `Content-Type` and the three `X-P3-*` HMAC headers with the unchanged body to **`env.P3_COMMAND_SERVICE.fetch`**. It forwards neither JWT nor service-token credentials. The downstream request uses the existing P3-20 logical URL for compatibility with the HMAC-bound exact pathname; that URL is **only a synthetic Request target on the service binding**, never a request to a public preview Worker. Downstream errors are sanitized; only the verified `202 Accepted` receipt is forwarded.
- These modules are **not imported by** `src/p3-disabled-bridge-worker.mjs`, the existing preview sentinel or any GitHub Actions production runner. No new Cloudflare route, trigger, cron or service binding exists in deployed configuration.
