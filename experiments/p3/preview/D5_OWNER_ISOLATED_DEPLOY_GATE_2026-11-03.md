# FISH118 D5 — Owner candidate isolated test deployment gate

Status: **authorized by owner for one isolated test deployment**; source and isolated CI do not themselves prove Cloudflare deployment or Android acceptance. Provider actions must be run with the owner's existing Wrangler login, with output reconciled before proceeding.

## Scope and non-goals

- Source branch: `feature/fish118-d5-owner-integration`. Deploy only after exact-head **Fishing P3 isolated source validation** success, no dirty tracked files, and fresh release build/manifest byte verification.
- A **new Cloudflare Pages Direct Upload project** `fishing-v3-owner-d5-test` receives the fully verified static V3 owner candidate. Wrangler returns an immutable deployment URL `https://<hex>.<project>.pages.dev`. Never reuse the approved read-only D5 reader project or deploy to public V2.
- The existing private same-origin owner Worker `fishing-auth-p0-test` receives only the exact reserved `/fishing/__v3_owner_candidate__/` static route, enabled behind `D5_OWNER_CANDIDATE_ENABLED=true`, with `D5_OWNER_PAGES_ORIGIN` pinned to the immutable test release. Its `/auth`, `/session`, `/api/v3` and other private publishing routes remain unchanged; the underlying trusted D3 gateway independently enforces owner session/CSRF and writes to the sandbox only.
- Preserve **exact original private pilot JS and CSS bytes** by copying from the **last owner-deployed local generated bundle** and checking both SHA-256 against the last deployed ignored Wrangler config. Do not rebuild the old pilot from changed D5 source, rewrite its hashes, or silently modify the old pilot. Preserve existing secrets, D1 bindings and Cron.
- Before deploying a Worker change, require **live current Worker version == operator-pinned previous version**, old private anonymous-denial proof, and same-origin public V2 digest. During dry-run and again immediately before deployment, reverify the version and public proxy. After deployment verify anonymous owner candidate GET, private pilot still denied, public V2 byte-equivalent, and candidate release pointer SHA equal to the immutable Pages source. No blind retries of uncertain writes.
- Explicitly excluded: real publishing tests without an owner-initiated action, new OAuth credentials, public V3 cutover, public V2 upgrade, D1 migration, new domain, more auth services, automatic offline GitHub writes, and any claimed field PASS before owner Android testing.

## Operator flow (Windows PowerShell, with existing Wrangler login)

1. Checkout the **exact latest verified source head** as a separate detached worktree, leaving existing local private configs and generated pilot files in the original checkout. This is a deliberate separate working copy, not a merge into main.
2. Run `experiments/p3/preview/tools/deploy-d5-owner-pages-test.ps1 -ExpectedHead <SHA> -ExpectedCiRun <RUN_ID>`. It verifies exact source/CI, builds and byte-checks the candidate and staging, **creates a new** isolated Pages project, uploads once and verifies release/manifest over HTTPS. On any uncertainty, inspect Pages **without repeating** the upload. Record `IMMUTABLE_PAGES_ORIGIN`, release ID and GitHub source head. Do not use the standalone Pages URL as an installed authenticated owner app.
3. Supply `-PreviousConfig` as an absolute path to the **ignored Wrangler config used for the most recently deployed** private Worker in the existing checkout, and `-PreviousGeneratedDir` as the absolute path to that checkout's `experiments/p3/preview/src/generated`. Verify the private Worker version using `npx wrangler@4.153.0 deployments status --name fishing-auth-p0-test`, and pass that precise version as `-ExpectedWorkerVersion`. Do not substitute a historical config/version if they differ.
4. Run `deploy-d5-owner-gateway-test.ps1` from the new worktree with `-ExpectedHead`, `-ExpectedCiRun`, `-PagesOrigin`, `-PreviousConfig`, `-PreviousGeneratedDir`, and `-ExpectedWorkerVersion` **without** `-Deploy`. It prepares a new *git-ignored* Wrangler config, preserves old pilot bytes and validates a dry-run. Stop if any preflight fails.
5. Repeat the **same verified invocation** with `-Deploy` only after the successful prepare result. It rechecks the Worker version/public V2 and makes one version-locked Worker deployment. Output should show `PASS: D5 OWNER PRIVATE TEST GATEWAY DEPLOYED` and the exact owner test URL `https://fishing-auth-p0-test.ginosega.workers.dev/fishing/__v3_owner_candidate__/`. If uncertain, record the operation outcome as **unknown**, inspect deployments, and never blindly redeploy.
6. Perform bounded Windows/Android owner-session, editing, Work Offline, draft recovery and denied-publication acceptance checks; do not call source CI or a 200/202 response field acceptance. Full application CI and eventual public D6 release remain separate gates.

## Evidence and reversibility

Save the operator's concise PASS lines, source/CI identity, previous/new Worker versions, immutable Pages URL, remote release/manifest hashes, and field observations to the active issue and canonical governance checkpoint. Do not copy raw credential-bearing logs into GitHub or chat. If a rollback becomes necessary, read current deployed version and reconcile outstanding D1 operations first; never automatically overwrite newer versions.

The standalone owner Pages project is intentionally publicly readable **only as static application bytes**, with no embedded owner session credentials or private D3 source. Authentication and publication require the separate same-origin private Worker; the main public reader and site remain separate.
