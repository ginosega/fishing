## Implemented

1. **Trusted exact-head canonical validator bridge:** [`../../src/trusted-sandbox-candidate.mjs`](../../src/trusted-sandbox-candidate.mjs) reads the immutable owner submission from the server-owned D1 operation store, not from browser-supplied files or a claimed `validated` flag. It requires an explicitly provided *server-owned* sandbox checkout rooted at an absolute path; checks exact sandbox repository ID `1430581407`, expected Git commit SHA via `git rev-parse HEAD`, a clean working tree, an allowlisted sandbox Git remote, and the true `pwa` path within the checkout, and then runs the established [canonical source-aware promoter](../../src/source-aware.mjs), including its full source inventory, schema, references, Markdown and real media checks. No Catch authoring or uploaded media is enabled in this initial text-only phase. The bridge cleans up through a trusted checkout-provider callback even if validation fails.
2. **Durable GitHub branch receipt:** [`src/d1-operation-store.mjs`](src/d1-operation-store.mjs) now supports `saveBranchReceipt` and `branchReceipt`, storing immutable expected `main_base_sha` and `pr_head_sha` under a specific active D1 lease and Validating state. A different owner/lease, changed SHA, expired lease or terminal state cannot overwrite the receipt. Exact receipt survives coordinator restart.
3. **Recovery-aware GitHub adapter:** [`src/sandbox-github-pr.mjs`](src/sandbox-github-pr.mjs) writes a new sandbox branch only after validating source and rechecking `main`, then **requires that the D1 branch receipt be saved successfully before trying to open a draft PR**. If branch creation succeeds but receipt saving fails, it stops; an unknown orphan branch requires manual reconciliation. If the branch and durable receipt match exactly, but no PR exists after a crash, the adapter may create *only* the missing draft PR after verifying the commit has the expected single parent. No merge or production branch write is possible through this adapter.
4. **Source-only dispatcher:** [`src/sandbox-dispatcher.mjs`](src/sandbox-dispatcher.mjs) composes the existing **D1 owner session and CSRF guard**, D1 idempotent acceptance, D1 leased state stepper, trusted checkout validation, sandbox-only GitHub App draft PR adapter and durable receipts. `accept` authorizes the caller before storing a bounded text-only Gear/KB snapshot. `step` is a trusted backend-only method, defaults to disabled, and advances only `Accepted → Validating → Checking` once it has verified exact sandbox source and PR identity. No code automatically progresses to Merging, Deploying, Verifying or Live. Errors after possible GitHub side effects return a non-success `NeedsReview` result; never silently claim success, reset a branch, or retry a missing receipt as though nothing happened.

## Unresolved hard prerequisites

1. **Authenticated exact-head acquisition:** `trustedCheckout` and `readMainSha` are **injected trusted server interfaces**. Local Git HEAD/cleanliness/remote URL checks are consistency evidence, *not cryptographic proof the worktree came from authenticated GitHub*. Before live use, implement/test a trusted provider that independently queries GitHub by the dedicated App installation, checks sandbox numeric repository identity, checks out **exact** commit SHA with server-held credentials and verifies it immediately before validation. Never accept a checkout path, HEAD, or candidate proof from the client.
2. **Owner session issuance:** The guard reads D1 sessions, but P3 does not yet issue its own sessions using a reviewed OAuth callback or bind the intended first-party cookie origin; real authorized browsing and revocation/security gates remain. No write-capable Worker endpoint has been enabled or deployed.
3. **Durable side-effect lifecycle:** The receipt supports branch-to-draft-PR recovery, but a crash after branch creation and **before** receipt durability still demands manual review. A service restart after an API failure and lease expiration must be exercised against real sandbox API state, with bounded retry/backoff and audit logging. No background processing or notification has been established.
4. **Sandbox contents and policy:** The private test repo's `main` remains **unprotected**, with only README, no canonical schema/media fixture or exact-head CI workflow. No automatic merge. Before first real PR, establish exact-head validation, and verify actual private-repo branch-rule capabilities under the owner's GitHub plan; do not assume a paid plan, change visibility, or buy services without approval.
5. **App permissions and release verification:** The currently granted dedicated App rights do not include `Checks: read`, needed by GitHub's private-repo check-runs API. This requires owner-approved change at the appropriate checkpoint, with only necessary read scope. Later exact PR head, CI, merge and hosted release proofs must be implemented before any Live claim.
6. **Cloudflare:** The new `0002` D1 migration has **not** been applied. The deployed P3 preview Worker remains disabled with `P3_WRITE_ENABLED=false`. Do not paste source-only Node modules into its Cloudflare code editor; they require a trusted Node execution environment, unlike the current static Cloudflare Worker. Do not expose D1 operation submission or GitHub write routes yet.
