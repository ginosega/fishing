## 1. Source deliverables

1. **`src/d2-unified-owner-session.mjs`** introduces one owner-session adapter that is deliberately compatible with AUTH-P0's actual `__Host-fish_p0_session` cookie format (**43-character base64url secret**), `sessions(token_hash,github_id,expires_at)` D1 table and `SHA-256(...).base64url` digest. It **does not** issue a second owner login, mint a cookie, contact GitHub or install any OAuth credentials. On every protected request, it checks server-side D1 owner ID, absence of bearer-auth, current unexpired session, a strict seven-day max validity window and same-origin request restrictions. Authenticated `GET /session` obtains a session-bound HMAC-SHA256 anti-CSRF token using a future server-only secret; unauthenticated response returns no CSRF or identity. Protected publishing POSTs require matching **Origin**, `Sec-Fetch-Site:same-origin`, explicit publish intent, bounded JSON content type, valid session and HMAC CSRF; status GET requires the same valid owner session. No raw cookie, CSRF secret or GitHub token is returned or logged.
2. **`src/d2-guarded-operations-api.mjs`** provides a small, **unrouted**, default-write-disabled `handle(Request)` boundary for `GET /session`, `POST /api/v3/operations` and owner-scoped `GET /api/v3/operations/{id}`. Session/status responses are `private, no-store`; mutations are unavailable until an explicit injected server-only `writeEnabled()` gate returns true. This source contains **NO GitHub API calls or signing keys** and does not expose an internal scheduled dispatcher. No generic write proxy or arbitrary PR/branch operation exists.
3. The D2 API permits only one **canonical v3 text-only Gear EDIT** package and empty media for the first slice; it imports and invokes the approved existing `pwa/src/handoff.mjs:validatePackage` and rejects unsafe property names, extra top-level parameters/browser repo selector, malformed or noncanonical compact JSON, unsupported operations/domains, oversized requests, missing base/changes/notes/picture structures and invalid original V3 source-aware package. It then REQUIRES a separately trusted injected `validateGearChange` adapter returning `{valid:true,repositoryId:1430581407,sourceRevision:<40-hex-SHA>}` before calling the existing isolated `d1-operation-store.mjs`. **That trusted fresh-source adapter is NOT yet implemented**; the tests use deliberate mocks. Real source-aware conflict detection must revalidate again immediately before GitHub write/merge.
4. The existing isolated D1 operation adapter writes an atomic Accepted + request snapshot/audit, hashes idempotency keys per owner/sandbox repo, returns stable status identifiers and detects a repeated key with changed content. D2's frontend response distinguishes **202 Accepted** (new) from **200 duplicate**, and returns **409 IDEMPOTENCY_CONFLICT** on mismatched content. Status is available only for the configured owner/repository and **never** infers `Live` from an Accepted record. Disabling the write gate returns a deliberately generic `503 TEMPORARILY_UNAVAILABLE`.
5. **`test/d2-guarded-operations-api.test.mjs`** adds **13 source-only adversarial tests** `D2-G01..G13`: matching P1 session table/digest, anonymous/other cookies, hard-disabled writer, once-only Accepted/duplicate/status, unauthorized/expired/revoked/other GitHub ID, cross-origin/missing Fetch Metadata, bearer/CSRF/intent/media/content abuse, rejection on failed injected source validation, status enumeration, revoked-session status denial, payload/unknown route handling, rejection of the legacy incompatible P3 session cookie and explicit idempotency conflict. In-memory SQLite DBs are distinct fixtures; test `writeEnabled:true` is **not** a deployed flag or production configuration.
