# FISH-TODO-118 WP3 — inline UTF-8 text in the atomic Git tree

**Source-only. Default OFF. No Cloudflare/D1/GitHub permission or Worker route activation.**

## The WP3 blocker addressed

The previous #470 source/media planner required **new** canonical JSON/Markdown Git blobs to already exist and independently GET-verified them before constructing a tree. New text is normally not in GitHub's object store, so the resulting publishing operation could fail before the first Git tree attempt. Original images are different: they are separately staged using signed owner/media tickets, D1 Unknown before POST, and independently verified Git blob bytes, and are only ever referenced by immutable blob SHA.

GitHub's official Git Trees API permits each create-tree entry to specify **either** `content` (GitHub creates a UTF-8 text blob) **or** `sha` (already staged blob), never both: https://docs.github.com/en/rest/git/trees?apiVersion=2026-03-10

## One immutable, fenced operation

- Canonical JSON and new/edited Markdown are still generated by the previously validated source promotion, record conflict and link checker. The planner computes the exact UTF-8 byte length and Git blob SHA-1 locally (using Git's `blob {bytes}\0` hash prefix), returns a frozen `verifiedText` proof and a bound inline `content` per new text entry. **It never needs a separate Git blob upload for new text.**
- The tree-step descriptor rechecks the complete content's UTF-8 byte count and Git blob SHA-1 against every verified text proof, applies the correct `pwa/` root mapping, and creates one JSON Git Data tree POST with `content` for text, `sha` for independently verified images and `sha:null` only for validated deletions. It includes the exact HTTP request **and** expected Git SHA tree entries in the single D1 Unknown fence fingerprint. No browser-supplied text, path or digest is accepted as a publishing proof.
- The existing #472 independent readback never trusts the create-tree 201 or inline Git tree POST body: it loads the independent GitHub root tree, compares **actual returned Git blob SHA** to the locally derived `expectedEntries` and rejects unexpected changes, collisions, text mismatch, and preexisting images. The existing D1 VerifiedTree receipt remains mandatory before downstream branch/commit/PR steps.
- Tighten #488 provider transport to max 32 tree entries, canonical `pwa/Gear`, `pwa/KB` and `pwa/Catches` paths only, path uniqueness, strict mode/type, exact `sha`-or-`content` shapes, UTF-8 size max 131072 per inline text entry, and no inline asset/binary content or new external hosts. No new database schema.

## Source-only tests and boundaries

Existing source-planner Gear/Catch/Knot/Notes tests are updated to prove that **novel text SHAs not yet available through GitHub GET** can still produce one valid immutable tree descriptor while original media staging is still checked. Additional tampered inline text, changed byte digest, malformed/oversize content, wrong path, duplicate case-folded path, sha+content and binary inline cases fail closed. GitHub transport and previous D1 lifecycle/Unknown/recovery unit tests continue to apply.

**Not yet proven:** actual hosted GitHub provider writes, deployed D1 table readiness, newly provisioned GitHub App write credentials, approved isolated same-origin OAuth/CSRF host, Windows/Android owner acceptance, or full WP3 exit. Those require a separately scoped owner-approved isolated hosted checkpoint. A passing source-only PR cannot mark public Live or authorize infrastructure.
