# ADR-0010 — Dedicated governance branch, main-only router, independent required CI

**ID:** ADR-0010
**Status:** accepted — owner-approved P5 activation; required branch rules and main router installed
**Scope / search tags:** governance architecture, main router, separate branch, CI, FISH108, no Pages deployment, branch protection
**Context:** The owner asked to complete a reliable governance system independently of PWA V3, with automatic structural enforcement before adoption. Installing a workflow executable on `main` would match the existing PWA production push filter and potentially redeploy V2, whereas retaining only per-change assistant checks would not provide permanent enforcement.
**Decision:** Keep the five current governance docs, indexed decisions and structural validator/workflow on one protected canonical `governance/project-ops` branch, and publish only a small `PROJECT_ROUTER.md` plus the unchanged `NEW_CHAT_PROMPT.md` on default `main`. Future governance PRs target the dedicated branch and run required `governance-docs` plus existing `fishing-merge-ready` checks. **Adopted:** Branch rules now require those checks, and the main router was merged at `fc85bd38c4c688026700971b4c2d463c293eebf3`.
**Alternative considered / why rejected:** (1) Merging executable workflow into public `main` risks an unrelated public V2 Pages redeployment; (2) leaving the rich docs both on main and governance branch creates two active authorities; (3) assistant-only per-change checks lack merge-blocking CI enforcement; (4) weakening FISH108 or using [skip ci] would bypass approved application safeguards.
**Reconsider only if:** GitHub enables a genuinely independent automatically required check on main with no application deployment or owner explicitly approves a different source/CI architecture that preserves original application release gates.
